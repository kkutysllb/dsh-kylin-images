# GPT-Image-2 样式库

把用户的一句话需求变成可执行的图像提示词。**先检索，再写**——不要凭记忆编模板。

## 何时使用

- 用户描述了一个画面但没给风格/构图/比例；
- 用户问「这种效果用什么风格/模板」；
- 用户要给已有提示词提改进意见。

## 工作流

1. **检索**：`img_library`。匹配顺序：**分类 → 风格标签 → 场景标签 → 近邻案例**。
   参数：query（关键词，中英均可）、category（如 cat-infographic）、styles、scenes、tags。
   需要「该用哪套模板」的判断时加 suggest=true，会返回 2-3 个候选与命中理由。
2. **候选 ≥2 且分差 ≤2，或返回了 fallback**：**先问用户选哪个**，给一句话理由，不要自己猜。
3. **套模板**：记住模板 id，用 `img_compose` 时传 templateId=...，
   工具会把该模板的**避坑指南**自动并入提示词约束段。
4. **写提示词**：六块结构——主体与任务 / 构图与布局 / 视觉风格与材质 /
   文字与标注 / 比例与输出格式 / 约束与负面细节。用 `img_compose` 预览（零成本），
   确认无误再 `img_generate`。
5. **输出**：先给可复制的提示词，再给选中的模板名与命中的案例 id。

## 输出默认

- **跟随用户语言**：中文请求就用中文写提示词（上游技能同款约定；本工具的编译器会自动把
  结构化字段翻成英文提示词主体，画面内文字保持源语言）。
- 约束要具体：精确文字、宽高比、可读标签、层级、要避免的伪影。
- 要多个方案时，复用同一套模板，只变主体/构图/配色/场景。

## 常见坑（来自样式库的避坑指南）

- 不给模糊指令：明确「平台 + 比例 + 布局」；
- 强制文字锁定：要求画面文字逐字准确，禁止乱码与占位；
- 中空界面（车机/智能家居）比例必须写在最前面；
- 截图类要指定平台特征（蓝勾 / 音乐碟片 / 双列瀑布流），否则模型会混搭。
