## 背景

麒麟（QiLin）与 DSH 双引擎升级后，应用内「语言」设置升级为**宿主托管偏好**
（`@qilin-agent/client-locale` 的 LocaleRuntime：账户菜单切换、存宿主设置、
跨浏览器共享；`navigator.language` 只是无显式选择时的临时兜底）。宿主壳层与
已升级的同族插件（dsh-super-ppts）都跟随该偏好，而本插件 client.js 仍以
`navigator.language`（浏览器 / webview 环境语言）判定双语——两个信号源一经
分叉，设置页在中文界面下钉死英文（侧栏「Vision model / Image studio」、正文
全英文），双引擎同时暴露。

## 修复

### 双语接入宿主 locale 服务（`client.js`）

- `inject` 声明补上 `locale`（`package.json` 的 client.inject 早已声明
  `@deepseek-ai/dsh-client-locale`，此前模块侧从未消费）；
- `apply()` 头部：`ctx.locale.register('kylinImages', { zh, en })` 注册命名空间
  字典（经 `ctx.effect` 挂接、随插件卸载回收），`t = ctx.locale.bind('kylinImages')`
  ——译函**调用时读当前应用语言**，账户菜单切语言即时生效（label thunk 本就
  每次投影重读，无需重注册）；放在导航字形 effect 之前，保证首帧即用对语言；
- **字典摊平**：locale 字典要求扁平，嵌套的 `kindHint` 摊平成
  `kindHint.<kind>` 点键注册；取用侧新增 `kindHint(value)`（先查点键、再回退
  嵌套对象），locale 绑定译函与旧兜底译函两种实现通吃；
- **老引擎兼容**：`ctx.locale` 缺席（旧 DSH 等）时自动落回原 navigator
  兜底译函，行为与 0.1.1 完全一致。

## 验证

- **169 项测试**全过（新增 3 项：inject 契约改为 `['slots','locale']`、locale
  注册摊平字典 + t 绑定断言、无 locale 面时 navigator 兜底不炸），
  `tsc --strict` 零错误；
- 装机验证：`plugin_manager install_bundle` 结果 applied，desktop profile
  线上副本与工作区 client.js sha256 一致；
- 行为判别：桌面 webview `navigator.language` 非 zh 的环境（出问题的现场），
  修复后设置页跟随应用「中文」显示；切 English 应整页跟随。

## 升级说明

- 无破坏性变更；通道配置与 vault 均兼容。
- 设置页语言从「跟浏览器环境」改为「跟应用内语言设置」：这是对升级后宿主
  契约的适配；需要按浏览器语言显示的场景（旧引擎）行为不变。
